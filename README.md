1. 事务指的是构成单一的逻辑工作单元的操作的集合
在本Demo中可以代表钱从一个账户转移到另一个账户

2. 事务具有ACID的特性
原子性在该代码中表现为需要收到保护的银行汇款事务的操作包括：
查找汇款表并锁住、按照account号对汇款方和汇入方Account表进行从小到大排列依次读取并锁住、对两个表依次进行balance操作、操作完成之后依次释放所有锁，由事务管理器进行commit
如果有一个出错则通过async with session.begin()的事务管理进行全部回滚。

3. 调度捕获的是影响事务并发执行的关键操作，在代码中以async,await等关键字来实现。
不同于进程之间的切换可以强制断点，调度只能在await中进行转换。

4. 为保证幂等，每一笔转账具有唯一的trade_no,一行TransferRecord
对于核心的数据库交互函数submit_transfer,先进行查流水的事务再跑业务事务

5. 死锁情况解决方案
按照account号对汇款方和汇入方Account表进行从小到大排列依次读取并锁住

6. 限流
通过./services/limiter.py中调用asyncio.Semaphore()实现

7. 总结
通过行锁，满足2PL(如果用一句话概括，我会说：就是保证一个事务先只增加锁住的数据项再只减少锁住的数据项，按照最后一个增锁的时间戳对事务进行排序)，保持银行汇款操作的事务原子性，再加上幂等等异常校验的实现防止超出业务逻辑的各种错误出现。

8. test中所模拟的情况
（1） 限流阈值的提高使得请求竞争行锁的情况下能够正确全部运行完成
（2） 双向并发转账可能造成的死锁情况
（3） 长事务抢占行锁，后到请求/锁等待超时 -> 回滚+记录失败流水
（4） 并发数过限流阈值直接返回繁忙
（5） 扣款后、入账前抛异常 -> 完整回滚，余额不变，流水 FAILED
（6） commit 成功但响应前断网 -> 查询可查到 SUCCESS，重试不重复转账

9. 并发控制的其他方法：
基于时间戳的方法，基于有效性检查的协议，多版本机制（mysql用InnoDB 可重复读 (RR) 隔离级别，普通不加锁的情况走快照读）等方案进行实现。
